## 第二天：手機與後台驗收（50 分鐘）

前 25 分測商品、訂單與通知，中間 15 分測真人接手與 FAQ，最後 10 分記錄結果與排錯。老師的程式測試在建置階段先做完，不要全部擠在這 50 分鐘。

測試前由老師確認手機測試帳號、管理員收通知帳號與測試商品。用虛構測試名稱；記下初始庫存。按鈕或手動輸入同一個完整固定格式，都可能建立訂單，並不是只有按鈕能下單。

| 編號 | 輸入或動作 | 應該看到 | 結果／時間 |
|---|---|---|---|
| D2-00 | 未登入開後台；再登入 | 未登入看不到資料，登入才可操作 | |
| D2-01 | 按「瀏覽商品」 | 聊天室出現文字，收到商品輪播 | |
| D2-02 | 按某商品的預約鈕一次 | 聊天室出現固定格式；後台多 1 單、庫存減 1 | |
| D2-03 | 同一筆訂單確認兩端手機 | 客人收到確認，管理員收到通知；分別記結果 | |
| D2-04 | 自己打「我要預約」 | 引導選單，訂單數不變 | |
| D2-05 | 問 FAQ 原句與換句話說 | 依第一天資料回答，事實一致 | |
| D2-06 | 按「聯絡客服」，再按一次 | 第一次才回覆並通知；第二次只延長時間 | |
| D2-07 | 接手中傳一般問題，再按預約 | 一般問題 AI 不回；預約仍處理，接手時間延長 | |
| D2-08 | 後台結束真人接手，再問 FAQ | 啟用 AI 的客人恢復回答 | |
| D2-09 | 後台關閉某客人 AI，再結束接手 | 一般問題仍不呼叫 AI；測完由老師協助恢復設定 | |
| D2-10 | 非接手狀態問 FAQ 沒有的事 | 引導人工，後台多一筆 FAQ 缺漏紀錄 | |
| D2-11 | 後台刪除剛建立的測試單 | 庫存只加回 1；再按刪除不得重複加回 | |
| D2-12 | 把測試商品設為 0／下架，再預約 | 不建單、不扣庫存；顯示無法預約 | |

手機驗收完成後，將測試商品與設定回復到課堂指定狀態；老師確認後再清理測試訂單。

## 老師協助的程式驗收（建置階段）

使用本機測試資料、模擬 LINE／Gemini 回應；不向真實客人送訊息。每人的 Codex 專案要各自跑一次。不能用別人的測試或舊版 S001 時段範例，代表這次商品系統通過。

| 編號 | 測試 | 通過條件 | 測試檔／結果 |
|---|---|---|---|
| T1 | 同一 webhookEventId 重送兩次 | 只有一單、一次扣庫存，不重複通知 | |
| T2 | 兩個不同使用者同時搶最後一份 | 一成功一失敗；庫存 0，只有一筆有效訂單 | |
| T3 | 下單中途故障，及重複刪單 | 失敗整筆回滾；刪單只回補一次 | |
| T4 | 接手到期前／後、永久停用 AI | 活動中延長；到期下一則可恢復；永久停用仍不回 | |
| T5 | 模擬 429、503、逾時與無效 JSON | 有替代回覆、不無限重試、不記成 FAQ 缺漏 | |
| T6 | 未登入直接呼叫後台 API | 看不到也不能修改資料；錯誤簽章拒絕，空事件 Verify 可回 200 | |
| T7 | 通知 API 失敗 | 訂單保留且標示通知待處理；重試不另建一單 | |
| T8 | 商品過期、名稱重複或舊卡片 | 過期拒絕下單；禁止同名；已改名的舊卡片引導重新選擇 | |
